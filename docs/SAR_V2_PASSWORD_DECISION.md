# SAR-v2 마스터 비밀번호 결정

**결정일:** 2026-10-10  
**상태:** 2026-10-10 사용자 결정, 키움·JB·나무 공통 미리보기 구현 기준  
**범위:** 새로 설정하는 자가복구 지갑의 로컬 보관함과 SAR-v2 비밀번호 조각

## 오늘의 결정

새 자가복구 지갑은 **마스터 비밀번호 하나**를 설정한다. 별도 복구 비밀번호를 설정하는 선택지는 제공하지 않는다. 같은 입력을 이 기기의 암호화된 로컬 보관함과 SAR-v2의 비밀번호 조각에 각각 사용한다. 두 암호화 경로는 독립적인 salt와 AAD를 사용한다. 비밀번호 원문, 니모닉, 완성된 비밀키는 서버로 보내지 않는다. 등록 과정에서 휴대폰·이메일에 대응하는 **개별 조각**은 서버에 전달되어 별도 키로 암호화된다.

고객 순서는 복구 구문 확인 → 마스터 비밀번호 설정·확인 → 이 기기의 6자리 간편 비밀번호 설정 → 휴대폰·이메일 인증 → SAR-v2 등록 완료다. 조각은 지갑 생성 시 고객 기기에서 2-of-3으로 분할된다. 로컬 보관함에는 복구 가능한 두 조각의 암호문을 저장하고, 원격에는 비밀번호로 암호화한 조각 하나와 휴대폰·이메일 인증으로 접근하는 조각을 각각 저장한다. 고객에게 조각 생성 시점을 인증 이후라고 설명하지 않는다.

새 마스터 비밀번호는 **8자 이상, 영문 대문자·소문자·특수문자를 모두 포함**해야 한다. 숫자는 선택 사항이다. 화면은 `위험`–`안전` 게이지와 네 조건의 충족 상태를 보여주고, 조건을 모두 충족하지 않으면 다음 단계로 진행하지 않는다. 이 게이지는 설정 조건 충족 표시이며, 추측 저항성을 보증하는 판정이 아니다. 키움은 보라, JB는 파랑, 나무는 연두 계열의 안전 상태 색을 사용한다.

## 복구와 기존 지갑

- 새 기기에 로컬 보관 데이터가 없다면 마스터 비밀번호만으로 서명하거나 지갑을 열 수 없다. `마스터 비밀번호 + 휴대폰`, `마스터 비밀번호 + 이메일`, `휴대폰 + 이메일` 중 두 조각으로 복구한다. 기본 안내에서는 휴대폰·이메일 인증을 명확히 보여준다.
- 복구가 끝난 기기에서는 원격 비밀번호 조각을 확인한 뒤 마스터 비밀번호와 새 6자리 간편 비밀번호로 두 조각을 로컬에 다시 암호화해 보관할 수 있다. 다음 결제·서명은 그 기기의 간편 비밀번호 또는 마스터 비밀번호로 열며 원격 인증을 반복하지 않는다. 고객이 `이번만 지갑 열기`를 고르거나 기기 저장이 실패하면 로컬 보관 없이 이번 작업만 진행한다.
- 로컬 보관 데이터 자체가 복사되었고 마스터 비밀번호도 노출되면, 그 데이터의 두 조각으로 지갑을 열 수 있다. 별도 복구 비밀번호를 두더라도 이 로컬 경로의 위험은 사라지지 않는다.
- 한 비밀번호를 두 용도에 쓰면 그 비밀번호 유출이 원격의 `비밀번호 + 인증 1개` 복구 경로에도 영향을 준다. 고객의 비밀번호 부담을 줄이는 대신 이 연결 위험을 수용한 사용자 결정이다.
- **기존 지갑의 암호문은 재암호화하지 않는다.** 이전 단일 비밀번호 지갑은 기존 마스터 비밀번호로, 2026-10-10 직전 분리형 설정에서 만든 지갑은 당시의 별도 복구 비밀번호로 원격 비밀번호 조각을 연다. 복구 화면에 이 예외를 안내한다. `휴대폰 + 이메일` 조합은 두 경우 모두 비밀번호 없이 동작한다.

## 구현·운영 경계

`apps/reference-bank-host/src/SarEnrollmentPanel.tsx`가 설정과 게이지를 표시하고, `sarMasterPasswordPolicy.ts`가 고객 입력 규칙을 정의한다. `App.tsx`는 같은 비밀번호를 `createLocalSarVault`와 `encryptPasswordShare`에 전달하되 각 함수의 salt·AAD와 암호문은 분리한다. 키움·JB·나무는 공통 호스트 흐름을 사용하고 색만 테넌트의 키컬러를 따른다.

현재 기기 잠금 해제 수단은 간편 비밀번호와 마스터 비밀번호다. 생체 인증으로 암호화된 로컬 보관함을 여는 호스트·기기 키 저장소 연동은 아직 없다.

현재 SAR-v2 서버 구현은 개발용 단일 BFF·Supabase 경계다. 휴대폰·이메일 조각은 별도 키로 암호화하지만 독립된 운영 주체·저장소는 아니다. 실자산 운영 전에는 조각 보관 경계와 복구 승인 정책을 별도로 검토해야 한다. 비밀번호 게이지나 2-of-3 조각 수만으로 운영 보안 승인을 주장하지 않는다.
