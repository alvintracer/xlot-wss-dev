# 월렛 결제 쇼케이스 · 2026-10-10

## 범위

- 키움·JB·나무 월렛 홈의 `보유 자산`과 `보내기 내역` 사이에 결제 섹션을 둔다. 화면 배치와 색은 각 tenant UI-kit 토큰을 따른다.
- `월렛 카드`는 발급 전 시각화, 월렛·EVM 체인 연결 선택, QR 결제 사용 내역을 보여주는 쇼케이스 화면이다. 연결 선택은 해당 브라우저의 로컬 저장소에만 남는다. 실물 카드 발급, NFC 결제, 승인망 등록을 의미하지 않는다.
- `월렛 POS`는 실제 EVM 수신 주소와 자산·수량으로 15분짜리 QR 결제 요청을 발행한다. 현재 지원 범위는 Ethereum, Polygon, Arbitrum, Base, BNB의 WSS 송금 가능 자산이다.
- POS는 QR/카드 탭을 제공한다. QR 탭은 기본이며, 받기 화면과 같은 자산·체인 선택 화면을 거쳐 원화 기준 또는 토큰 수량 기준으로 금액을 입력한다. 카드 탭은 NFC/실물 카드 승인 전 시각화다.
- POS 관리에서 기본 수신 월렛·자산·체인을 이 기기에 저장하고, 확정된 QR 결제를 기간·건별로 선택해 CSV로 내려받는다. 결제 요청 시점의 서버 원화 참고가와 기준시각을 함께 기록한다. 시세가 없으면 관련 CSV 칸을 비우며 공식 전자세금계산서로 표시하지 않는다.
- 결제 섹션의 카메라 버튼은 기존 호스트 QR 스캐너를 연다. 이미지 업로드도 같은 경로에서 쓸 수 있다.

## QR 결제 절차

1. 판매자가 POS에서 자산·체인·수량을 정한다. 서버는 세션 소유 월렛의 수신 주소를 조회해 `wss_qr_payment_requests`에 저장한다.
2. QR에는 `https://<host>/pay/<request-id>` 주소만 담는다. 외부 카메라로 열면 공통 진입 화면에서 결제할 금융사 앱을 선택한다. 금융사 앱 안 카메라로 스캔하면 현재 월렛에서 바로 결제 확인 화면을 연다.
3. 결제자는 서명 전 금액·받는 주소·네트워크 수수료·주소 확인 결과를 본다. 서버는 준비 요청의 체인, 자산, 원자 단위 수량, 받는 주소를 원본 요청과 비교하고 한 송금 의도에만 결제를 예약한다.
4. 기존 WSS 기관 인증·고객 서명·송금 제출 경로를 사용한다. POS는 송금 제출과 온체인 영수증 또는 기존 릴레이 상태를 조회해 대기/확인/실패를 표시한다. 조회 실패를 결제 완료로 표시하지 않는다.
5. 보내는 화면은 준비·서명·제출·확정 조회를 연속된 진행 상태로 보여준다. 제출 뒤에도 같은 결제 요청을 확인하며 확정 전에는 완료로 표시하지 않는다. 받는 POS는 승인 대기와 네트워크 확인을 구분하고, 확정 시 결제 수신 효과와 함께 사용된 QR을 흐리게 표시한다.

## 운영 경계

- DB 변경: `services/institution-bff/db/migrations/0024_wss_qr_payments.sql`.
- 원화 참고가 스냅샷과 확정시각: `services/institution-bff/db/migrations/0025_wss_qr_payment_reference_price.sql`.
- QR 결제는 기존 송금 정책, 잔액·수수료 검증, KYT, 기관 승인 절차를 그대로 따른다. 카드 쇼케이스의 로컬 연결 상태는 결제 권한으로 사용하지 않는다.
- 카드의 원화 사용 합계는 **확인된 QR 결제**를 현재 자산 시세로 환산한 참고값이다. 과거 결제 시점 환율을 고정한 회계 금액이 아니다.
- 기존 자동 검사와 320/360/390/430 CSS px 화면 검토를 마쳤다. 2026-10-11에 사용자가 PC POS QR을 나무 앱으로 결제해 성공했다고 보고했다. 이번 진행 화면 변경 뒤의 실기기 재검증과 키움·JB의 두 기기 결제 검증은 별도로 필요하다.
