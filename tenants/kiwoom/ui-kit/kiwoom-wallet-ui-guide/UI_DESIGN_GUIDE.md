# 키움 앱 임베디드 지갑 — UI Design Guide

**v1.0 · 2026.09.27 · 개발자 / 코딩 에이전트 전달용**  
**대상:** 첨부된 키움증권 앱 **간편모드**의 시각 언어를 유지하는 앱 내 디지털자산 지갑.  
**자료:** 사용자 제공 이미지 19장. 이 문서는 키움의 공식 디자인 시스템이 아니라 **스크린샷에서 역설계한 구현 기준**이다.

> **구현 목표:** “새 지갑 앱”을 디자인하지 않는다. 기존 키움 앱의 자산 기능이 확장된 것처럼 구현한다. 보라색 하나만 맞추는 것이 아니라 화면 바탕, 카드 폭, 글자 계층, 줄간격, 버튼 위치, 입력 방식, 상태 표현을 함께 맞춘다.

## 00. 먼저 읽을 것

| 구분 | 이 문서에서의 의미 | 구현 시 처리 |
|---|---|---|
| **관찰·측정** | 첨부 화면에서 확인한 구조·평면 색상·픽셀 경계 | 기본값으로 고정. 임의 리디자인 금지 |
| **추정·보정** | 폰트 이름, 논리 좌표, 글자 크기·굵기, 일부 글자 색 | 최초 단말 비교 후 조정. 공식 값이라고 표기하지 않음 |
| **지갑 확장** | 기존 화면 문법을 지갑 기능에 적용한 신규 설계 | 상품·채널 담당자 확인. 기존 앱에 이미 있는 기능이라고 주장하지 않음 |

**“완전 동일”의 마지막 조건:** 원본 폰트와 굵기 파일, 정식 아이콘·일러스트, 실제 앱의 논리 뷰포트/배율, 호스트 내비게이션 및 인증 SDK가 필요하다. 이 파일에는 폰트 파일을 포함하지 않는다. 제공 코드의 아이콘은 교체 가능한 임시 벡터이며, 로고 크롭은 검수용이다. 스크린샷으로 확인할 수 없는 애니메이션·탭 전환·네이티브 키패드 내부 동작은 동일하다고 보증하지 않는다.

### 지갑 적용 원칙 — 신규 설계

기본 진입안을 **자산 → 디지털자산**으로 둔다. 실제 앱의 진입 위치는 호스트가 결정한다. 루트 하단 메뉴에 `지갑`을 여섯 번째 탭으로 추가하지 않는다. 별도 took!/Traverse 브랜드 헤더, 연결하기 중심의 외부 Web3 앱, 검정 대시보드, 네온 보라 그라데이션을 만들지 않는다.

기존 고객 로그인·인증·권한·고객확인 컨텍스트를 사용한다. 지갑 진입 때문에 주민등록번호나 휴대폰 본인인증을 다시 수집하는 화면을 신규 구현하지 않는다. 첨부 인증 화면은 **폼 스타일과 인증 흐름 연결 방식**의 참고 자료이지, 지갑에서 동일한 개인정보를 재수집하라는 요구가 아니다.

서비스 화면은 지갑 선택, 원화 기준 조회·입력, 주소/QR 기반 송수신, 수신처·네트워크·수수료·정책 결과 확인, 고객 승인·복구 안내에 집중한다. 키·서명·체인 처리 결과는 지갑 코어가 제공하고 UI는 이를 표현한다. 수탁/비수탁, 지원 체인, 복구 프로파일은 화면 코드에 상수로 박지 않는다.

## 03. 좌표·배율·안전 영역

### 기준 좌표

18장의 앱 캡처는 모두 **648 × 1404 px**이다. 개발/비교 편의를 위해 이를 **360 × 780 logical px**로 정규화한다.

```text
scale = 648 / 360 = 1.8
logical_x = screenshot_x / 1.8
logical_y = screenshot_y / 1.8
```

이는 **비교를 위한 가정**이다. 원본 기기의 실제 CSS viewport, Android dp, DPR, 화면 확대율은 확인되지 않았다. “이 앱은 DPR 1.8”이라고 해석하면 안 된다. 실제 단말 측정 시 360 환산 기준을 보정한다.

| 구역 | 원본 px 대략값 | 정규화값 | 구현 규칙 |
|---|---:|---:|---|
| 캡처상 상태 표시줄 | y 0–49 | 약 27 | 앱에서 시계·배터리·LTE를 그리지 않음 |
| 앱/시스템 경계 | y 약 1318 | 약 732 | 시스템 내비게이션 영역과 앱 콘텐츠 분리 |
| 시스템 하단 영역 | y 약 1318–1404 | 약 48 | 실기기 inset 사용. 48을 제품 코드에 고정하지 않음 |
| 루트 하단 메뉴 | y 1221–1318 | 약 54 높이 | 호스트가 소유. 지갑 SDK가 중복 렌더링하지 않음 |
| 폼/상세 기본 좌우 | x 약 35–36 | 약 20 | 기본 gutter 20 |
| 루트 큰 카드 좌우 | x 약 21–22 | 약 12 | card gutter 12 |
| 카드 내부 글자 시작 | x 약 57–58 | 약 32 | 외부 12 + 내부 20 |

### 실제 앱 통합

WebView가 이미 안전 영역 안에 배치된다면 `hostHandlesInsets=true`로 취급하여 추가 padding을 넣지 않는다. edge-to-edge WebView만 호스트가 전달한 inset 또는 `env(safe-area-inset-*)`를 사용한다. **호스트 inset + CSS safe-area + 가상 시스템 바를 동시에 더하지 않는다.**

미리보기의 상태 표시줄/홈 인디케이터는 비교용 셸이다. `embed=1` 모드에서는 제거한다. 키움이 가진 루트 헤더·하단 메뉴 역시 제품 통합 시 호스트 소유 여부에 따라 한 번만 나타나야 한다.

### 반응형

360을 기준으로 하되 320 / 360 / 390 / 430 너비에서 확인한다. 전체 화면에 `transform: scale()`을 걸어 맞추지 않는다. 좌우 gutter는 20, 큰 카드 gutter는 12를 유지하고 콘텐츠 폭을 유동화한다. 중요 금액·수수료·수신 주소·오류문장은 잘라 숨기지 않는다. 본문 접근성 글자 확대에서는 행 높이와 CTA 영역도 늘어난다. 키보드가 올라오면 CTA는 호스트 키보드 회피 정책을 따르고, 포커스 필드가 보이도록 스크롤한다.

**색의 의미를 섞지 않는다.** 상승 핑크는 “송금 성공” 색이 아니다. 매도 보라/매수 코랄을 단순히 “받기/보내기”로 재명명하지 않는다. 새 지갑 일반 동작은 **주요 액션 보라 + 보조 액션 중립색**을 기본으로 한다. 실제 매매 기능일 때만 호스트의 매수/매도 체계를 따른다. 상태는 색만으로 구분하지 않고 문구·아이콘을 함께 둔다.

### 딤·그림자·그라데이션

일반 시트 딤은 `rgba(0,0,0,.50)`를 기준으로 한다. R15의 흰 배경 위 딤은 약 #7F7F7F로 관찰된다. 가이드 오버레이는 더 진하지만 정확한 알파·색은 추정값이다. 일반 카드는 `box-shadow: none`이다. 상단/하단 고정 영역의 가벼운 경계는 허용하되 카드마다 부유 그림자를 넣지 않는다. 그라데이션은 R13/R17처럼 **도입 화면 하단**에 한정하고, 자산 총액 카드에 강한 보라 그라데이션을 넣지 않는다.

## 05. 타이포그래피

### 폰트 연결

스크린샷만으로 원본 서체 이름을 확정할 수 없다. **호스트가 실제 사용하는 한글/숫자 폰트와 weight 매핑을 그대로 상속**한다. `Pretendard`, `Noto Sans KR`, 시스템 폰트 중 하나가 원본이라고 단정하지 않는다. 미리보기는 설치된 `Noto Sans KR / Noto Sans CJK KR / Apple SD Gothic Neo / Malgun Gothic / sans-serif` 순으로 표시하므로 환경별 줄바꿈이 달라질 수 있다.

프로덕션에서 `--kw-font-family`를 호스트 토큰으로 지정한다. 임의 웹폰트 다운로드, 외부 CDN, 임의의 별도 숫자 폰트를 도입하지 않는다. 원본과 정확하게 맞추려면 글꼴부터 맞춘 뒤 크기·행간을 미세 조정한다.

### 숫자·문장 규칙

원화는 `1,234,567원`, 토큰은 `123.4567 USDC`처럼 값과 단위를 분리해 내부 모델에 저장한다. 숫자와 단위를 붙여 렌더링하는 것은 표시 규칙이다. 토큰 정밀도는 asset decimals/표시 정책을 따른다. 네트워크가 다른 동일 심볼은 별개 자산이다. 가격의 소수점 자릿수를 참조 화면의 해외주식 `4자리`로 강제 통일하지 않는다.

주요 금액이 길어지면 먼저 본문 폭과 단위 배치를 조정한다. 승인 화면의 금액을 말줄임표로 숨기지 않는다. 주소는 목록에서만 `0x12ab…90cd`로 줄일 수 있고, 검토 화면에는 전체 주소 보기·복사가 가능해야 한다. 숫자와 거래 상태는 실데이터를 쓰며 미리보기 예시값을 제품 기본값으로 남기지 않는다.

문구는 `보내기`, `받기`, `다음`, `확인`, `보내기 전에 확인해주세요`처럼 짧고 자연스럽게 쓴다. `Transaction`, `MPC`, `Gas sponsorship`을 주요 사용자 문구로 노출하지 않는다. 필요할 때 `네트워크 수수료`와 `복구 방식`의 상세 설명에서 풀어 쓴다.

## 07. 화면 셸

### A. 루트 셸 — 회색 바탕

```text
[호스트 시스템 상태 영역 — 앱 UI에서 제외]
[루트 헤더: 기존 로고 / 자산 / 검색·알림]          약 60
[채움형 카테고리 탭: 전체 / 디지털자산]             지갑 확장
[총액 또는 요약]
  [큰 흰색 카드]                                 외부 12 / 내부 20
  [큰 흰색 카드]
[호스트 하단: 탐색 | 관심 | 자산 | 혜택 | 메뉴]       54
[시스템 하단 inset — 호스트 처리]
```

루트 헤더는 스크롤 정책을 호스트에 맞춘다. 임의의 다중 sticky 헤더를 겹치지 않는다. 지갑의 루트 화면에서는 `자산`만 활성 상태다. 검색·알림 아이콘은 허용된 호스트 동작이 있을 때 표시한다.

### B. 상세 셸 — 흰색 바탕

상단 뒤로/축소, 제목, 우측 필요한 동작. 주요 값 → 보조정보 → 섹션 순서. 섹션 구분은 R02/R03처럼 넓은 여백 또는 밝은 회색 띠를 사용한다. 하단 고정 액션을 쓸 때 루트 메뉴를 동시에 두지 않는 것을 기본안으로 한다. 실제 호스트 전환 정책을 우선한다.

### C. 절차 셸 — 흰색 바탕

헤더 높이 48, 가운데 절차명, 좌측 뒤로, 우측 닫기. 하단 약 2 높이의 보라 진행선. 본문 시작은 헤더 아래 약 24. 큰 안내 제목 아래 입력 콘텐츠. 하단 단일 CTA 높이 52, 좌우 20, 하단 20 + 필요한 inset. 진행선은 실제 사용자 단계와 일치시킨다. 인증 모달이 열렸다고 임의로 100%를 표시하지 않는다.

`닫기`는 기본적으로 지갑 진입 화면으로 복귀한다. 작성 중 정보가 있으면 이탈 확인을 거친다. `뒤로`는 직전 단계로 돌아가 입력값을 유지한다. 인증이 끝난 후 이전 단계로 돌아가 수신처/금액이 바뀌면 기존 승인 유효성을 해제한다.

### 밑줄 탭

## 09. 카드·자산행·상세 데이터

### 큰 카드

흰색 배경, 외부 가로 12, 내부 가로 20 / 세로 24–28, radius 24, 그림자 없음. 카드 제목은 20/30 또는 정보량에 따라 20/28. 하나의 카드 안에서 제목, 탭, 리스트, 더보기의 위계를 유지한다. 새로운 정보를 넣을 때 카드 수를 불필요하게 늘리지 않는다.

### 자산행

```text
[38 아이콘] [USDC                 ] [1,234,567원]
            [Ethereum · 900 USDC ] [약정/변화/상태]
```

왼쪽 정보와 오른쪽 금액은 `minmax(0,1fr) auto` 또는 동등한 native layout으로 분리한다. 긴 이름은 일반 목록에서 한 줄 말줄임 가능. 금액은 우측 정렬. 보조 네트워크명은 12–14. 아이콘과 글자 사이 10–12. 원본 주식의 국가 배지를 지갑의 네트워크 배지로 바꾸는 것은 **신규 확장**이므로 asset master가 제공하는 네트워크 표시를 사용한다.

가상자산 로고는 공식/승인된 에셋을 사용한다. 예제의 동그란 티커 글자는 임시다. USDC/USDT처럼 로고만 보고 혼동하기 쉬운 자산은 이름·네트워크를 동시에 보인다.

### 확인용 데이터 행

왼쪽 라벨 14/20, 오른쪽 값 16/24. 수신 주소·네트워크·수수료·수취 금액은 충분한 폭을 준다. 주소는 줄바꿈 가능, 단위는 값과 붙여 읽힌다. 최종 확인 화면에서 필수 정보를 가로 스크롤 안에 넣지 않는다.

## 10. 입력창·금액 입력·검증

기본 필드는 **밑줄형**이다. R14/R16을 기준으로 라벨은 회색 12–14, 입력 완료값은 18, placeholder는 16, 기본 선은 1px 연회색. 포커스는 보라 선, 오류는 오류색 선 + 아래 12 크기 설명. 외곽이 둥근 테두리형 입력창을 모든 필드에 적용하지 않는다. 테두리형 사각행은 R15의 **선택 항목** 용도와 구분한다.

필수 상태: `empty / focused / filled / invalid / disabled / readOnly / validating`. 오류는 `입력 오류`보다 `받는 주소를 다시 확인해주세요`처럼 조치를 알려준다. 서버/SDK 검증 중에는 성공 표시를 미리 하지 않는다.

### 원화 금액 입력 — 지갑 확장

대표 입력은 `보낼 금액`과 큰 원화 값으로 구성한다. 아래에 환산 토큰 수량, 시세 기준시각, 견적 만료 정보를 적절한 밀도로 보여준다. `전액`은 사용 가능 수량·수수료·정책을 반영한 코어 계산 결과로 채운다. `원화 입력 → 토큰 수량 확정 → 최종 검토`를 구분하고, 검토 화면 진입 후 시세 갱신으로 수량을 조용히 바꾸지 않는다.

자산 수량은 정수 최소단위 문자열/정밀 십진 라이브러리로 처리한다. JavaScript `number`만으로 토큰 잔액·수수료를 계산하지 않는다. UI는 표시용 문자열을 받아도 거래 모델에는 원본 정밀값을 유지한다.

### 키보드

주소 입력은 붙여넣기/QR 동작을 지원하되 시스템 클립보드 접근·카메라 권한은 사용자 동작과 호스트 정책에 따른다. 키패드의 숫자 배열·암호화·보안 동작을 사진처럼 직접 흉내 내지 않는다. 주민번호·PIN·인증 입력은 **기존 호스트 보안 입력/인증 SDK**를 호출한다. 데모는 일반 HTML 입력이며 보안 키패드 구현물이 아니다.

## 11. 바텀시트·모달·안내막

### 선택 시트 — R15 기준

바탕 딤 50%, 흰 시트, 상단 곡률 16, 좌우 20. 우상단 닫기 44 터치 영역. 원본에는 **drag handle이 보이지 않으므로 기본으로 추가하지 않는다.** 제목은 20/30. 항목 글자는 16/24·600, 항목 높이 52, radius 16, border 1, 간격 10. 항목 수에 따라 콘텐츠 높이를 결정하고 긴 경우 시트 내부를 스크롤한다.

선택된 네트워크/지갑은 체크 아이콘과 텍스트로 표시한다. 색만 바꾸지 않는다. 시트의 스크림 클릭과 Android back은 안전한 선택 단계에서만 닫기로 연결한다. 최종 승인 진행 중에는 닫기/취소 가능 여부를 코어 상태에 맞춘다.

### 키보드/접근성

웹에서는 `role="dialog"`, `aria-modal="true"`, 제목 연결, 포커스 이동/가두기/복귀, Escape 동작을 구현한다. native에서는 동등한 접근성 포커스를 구현한다. 배경이 시각적으로 어두워도 스크린리더/탭 이동으로 배경 액션을 실행할 수 있으면 안 된다.

### 로그인 게이트 — R01/R03

특정 비공개 영역 위에 잠금과 `로그인이 필요해요`를 둔다. 샘플 개인 잔액을 실제 고객의 잔액인 것처럼 뒤에 그리지 않는다. 실데이터는 인증 전 로딩하지 않거나 정책에 맞춰 가린다. 게이트 클릭은 호스트 로그인으로 연결하며 복귀 경로를 유지한다.

### 기능 안내 — R05

최초 1회·사용자 닫기 가능. 현재 사용자에게 실제 제공되는 기능만 안내한다. 매번 진입할 때 어두운 가이드를 강제 노출하지 않는다. 첨부 화면의 손가락·장식·그라데이션 테두리는 승인된 에셋이 있어야 동일하게 재현할 수 있다.

## 12. 아이콘·일러스트·브랜드 에셋

일반 아이콘은 20–24, 기본 시각 선 굵기 약 1.5–1.8, 둥근 선 끝을 시작값으로 한다. 배경 원이 있는 설명용 아이콘은 40–64까지 별도 계층이다. 하단 내비게이션은 아이콘 22–24 + 글자 12. 모든 아이콘에 원형 배경을 자동으로 추가하지 않는다.

**원본 아이콘 세트는 확인되지 않았다.** Lucide/Material/SF Symbols 중 하나가 원본이라고 적지 않는다. 제공 SVG는 임시 대체다. 최종 에셋 교체 후 실제 보이는 선 두께와 광학 크기를 검수한다. 각 아이콘 SVG의 viewBox만 같아도 시각 크기가 같지는 않다.

로고, 캐릭터, 보상 일러스트를 emoji로 대체하지 않는다. 패키지의 `kiwoom-logo-preview.png`는 R10에서 자른 검수용 이미지이며 정식 앱에 넣는 자산이 아니다. 정식 로고는 호스트가 렌더링하는 방식을 우선한다. 폰트 파일은 제공하지 않는다.

아래 화면은 첨부 앱에 존재한다고 확인된 화면이 아니다. 기존 앱 문법으로 새 지갑을 구현하기 위한 설계안이다. 프로토타입의 잔액·주소·수수료·시간·정책 결과는 모두 가상값이며 견적 또는 실제 서비스 정책이 아니다.

|---|---|---|---|
| W00 | 미가입/지갑 없음 · 루트 | 기존 자산 헤더, 설명, 지갑 만들기, 복구 진입 | R07/R17 |

### W01 — 홈

원화 총액은 가장 먼저 읽히고, 토큰별 잔액은 하위 카드에서 확인한다. `내 지갑` 선택은 시트를 연다. 여러 지갑 슬롯이 없으면 불필요한 선택기를 표시하지 않는다. “거래소 연결”, “외부 지갑 가져오기”, “연락처 송금”은 지원 capability가 있을 때만 추가한다. 복구 프로파일이 다른 지갑도 같은 시각 셸을 쓰고 설명과 허용 액션만 달라진다.

버튼은 **받기: secondary / 보내기: primary**를 기본으로 한다. 자산행에는 `심볼 + 네트워크`를 함께 표시한다. 잔액 로딩 중에는 실제 0원으로 보이지 않도록 스켈레톤/로딩 상태를 둔다. 가격을 받지 못하면 잔액과 원화 평가 불가를 구분한다.

### W03 — 받기

자산과 네트워크를 선택한 다음 **그 네트워크의 실제 수신 주소**로 QR을 생성한다. 필요한 destination tag/memo는 주소와 별도 값으로 명확히 제공한다. QR은 라이브러리/SDK로 생성·검증하고 장식용 패턴을 주소 QR처럼 사용하지 않는다. 이 패키지의 미리보기는 의도적으로 **QR 자리표시자**를 사용한다. 주소 복사는 전체 원본값을 대상으로 한다.

### W04–W06 — 보내기

수신처 입력 → 주소 형식/체인/tag 검증 → 금액 입력/수수료 견적 → 정책·KYT 결과 → 최종 확인 → 호스트 인증·서명 승인의 순서를 상태로 관리한다. 일부 조회는 병렬 실행할 수 있지만 유효하지 않은 수신처/만료된 견적으로 승인 버튼이 활성화되면 안 된다.

최종 확인 화면에서 **수취 자산, 토큰 수량, 원화 참고가, 주소, 네트워크, tag/memo, 네트워크 수수료, 수수료 부담주체**를 구분한다. 송금 금액에서 공제되는 수수료인지 별도 비용인지 실제 견적 모델에 맞춰 표시한다. `수수료 무료`는 실제 대납 조건/한도/유효기간이 확인된 경우만 표시한다. 확인 화면 이후 금액·네트워크·주소가 바뀌면 재검증·재승인이 필요하다.

### W09 — 복구/수탁 표시

설정과 복구 화면은 실제 지갑 프로파일이 제공한 단계만 표시한다. 화면에 고정된 `MPC 2-of-3` 또는 `SAR 2-of-3` 시나리오를 넣지 않는다. 복구 인증, 새 기기 등록, 동의, 서비스 안내는 UI가 담당하고 암호학적 복구는 코어가 담당한다. 일반 서비스 UI에서 시드/키를 서버로 전송하거나 “관리자가 복구 완료”라는 허위 단계를 만들지 않는다.

수탁 연계가 필요하면 모드 표시·동의·대상 서비스로의 인계만 이 계층에서 지원한다. 이 안내 가이드가 수탁 전환 로직·키 이전 설계를 정의하는 것은 아니다.

| 월렛 코어 | 주소/잔액·수수료·거래 상태·키/서명·복구·RPC 결과 | UI의 임의 성공 플래그를 거래 확정으로 사용 |

`src/wallet-ui-contract.ts`는 위 구분을 위한 최소 시작점이다. 상품이나 코어 API의 실제 명세를 대체하지 않는다. 지갑 capability가 없는 항목은 비활성 장식으로 남기지 말고 숨기거나 적절한 신청 흐름을 제공한다.

특히 고객 최종 승인 UX는 **화면 확인 = 서명 완료**가 아니다. UI가 거래 intent와 유효한 quote를 확정해 코어의 승인 흐름에 넘기고, 인증/서명 결과는 정해진 보안 경로로 처리한다. 개인키·복구구문·인증 비밀은 UI 이벤트 로그나 분석 SDK에 포함하지 않는다.

## 16. CSS/컴포넌트 구현 규칙

제공 CSS 클래스는 `kw-` prefix를 사용한다. 호스트의 전역 `button`, `input`, `h1`을 덮어쓰는 전역 reset을 추가하지 않는다. reset은 `.kw-root` 안으로 한정한다. 패키지의 `body` 스타일은 독립 미리보기에만 사용한다.

```css
/* 실제 호스트가 제공하는 값을 연결한다. 예시 변수명은 호스트 계약에 맞춘다. */
.kw-root {
  --kw-font-family: var(--host-font-family, inherit);
  --kw-safe-top: 0px;     /* 호스트가 inset을 이미 처리하면 0 */
  --kw-safe-bottom: 0px;
}
/* 외형은 토큰으로 관리. 페이지마다 다른 보라색과 radius를 만들지 않는다. */
```

필수 컴포넌트: `RootShell`, `FlowShell`, `AppHeader`, `BottomActionBar`, `PrimaryButton`, `SecondaryButton`, `PillTabs`, `UnderlineTabs`, `LargeCard`, `AssetRow`, `DataRow`, `UnderlineField`, `ChoiceSheet`, `InlineNotice`, `StatusView`, `LoginGate`, `RecoveryEntry`.

컴포넌트마다 모든 상태를 디자인한다. 오류는 기존 콘텐츠 높이를 무너뜨리지 않게 자연스럽게 확장한다. 중요한 내용을 카드 높이에 억지로 맞춰 자르지 않는다. 스크롤 영역은 하나를 기본으로 하되 시트 내부 스크롤은 분리한다. fixed CTA는 문서 전체가 아니라 실제 임베디드 뷰포트에 고정한다.

스마트폰 native/Flutter/React Native에서도 색상·공간·타입·상태 규칙은 동일하게 적용하되 CSS px를 dp/sp로 기계적으로 복사하지 말고 실제 캡처로 비교한다.

## 17. 접근성·사용성 검수

작은 아이콘의 시각 크기는 유지하되 터치 영역은 이 가이드의 구현 기준으로 최소 44×44를 확보한다. 이는 스크린샷에서 측정한 영역이 아니라 지갑 확장 검수 기준이다. 플랫폼의 더 큰 최소 터치 요구가 있으면 그것을 우선한다.

색상만으로 상승/하락/성공/오류를 구분하지 않는다. 키보드 포커스는 숨기지 않는다. 이미지 아이콘 버튼에는 의미 있는 label을 제공한다. disabled 상태 외의 핵심 본문은 연한 회색으로 낮추지 않는다. 실제 글꼴·크기로 대비와 가독성을 검수하고, 이 문서의 토큰을 썼다고 접근성 인증이 완료됐다고 말하지 않는다.

시트는 닫은 뒤 원래 트리거로 포커스가 돌아온다. 스크린리더는 총액과 단위, 네트워크, 주소, 수수료를 순서대로 읽을 수 있어야 한다. 시스템 글자 확대·reduce motion 설정을 존중한다. 긴 원화값, 42자 EVM 주소, 긴 체인명, tag/memo 유무, 두 줄 오류를 테스트한다.

| 루트 카드/리스트 | R10 | 바탕, 카드 x/폭/곡률, 제목·행 baseline, 하단 메뉴 |
| 단일 폼 | R16 | 헤더, 제목, 라벨, 밑줄, 오류, disabled CTA |
| 바텀시트 | R15 | 딤, sheet 상단, title, 닫기, 선택행 높이·간격 |
| 주요 버튼/숫자 | R04/R09 | 색상, radius, 텍스트 크기, footer 위치 |

1. 비교 대상 원본의 앱 영역과 구현 캡처를 같은 논리 너비로 정규화한다. 시스템 바와 개인정보 마스킹 구역은 비교에서 제외한다.
2. 원본과 구현을 50% 겹치거나 나란히 놓는다. 색보다 먼저 **큰 경계/가로 여백/세로 위치**를 맞춘다.
3. 호스트 폰트 적용 → 제목·본문 글자폭/줄바꿈 → 행간/baseline → 아이콘 광학 크기 → 색상 순서로 보정한다.
4. JPEG 비교는 한 픽셀씩 완전 동일한 RGB를 강요하지 않는다. 평면 내부 중앙값/최빈값과 실제 시각 인상을 함께 본다.
5. 동등한 화면을 구현한 뒤 시각 승인한다. 새 지갑 화면은 기존 주식 화면과 콘텐츠가 다르므로 원본 전체와의 차이 비율로 “일치율”을 계산하지 않는다.

### 권장 수용 기준 — 프로젝트 제안값

| 항목 | 기준 |
|---|---|
| 주요 가로 경계 | 기준 360 환산에서 대략 ±1 logical px 이내 |
| 주요 세로 위치 | 동일 콘텐츠·폰트에서 대략 ±2 logical px 이내 |
| 평면 색 | 채택 토큰 사용, JPEG 오차를 감안한 중앙값 비교 |
| 글자 | 동일 서체/weight 이후 줄 수·폭·baseline 확인. 대체 폰트 단계는 임시 |
| 레이아웃 | 320/360/390/430에서 가로 overflow 없음, CTA 내용 가림 없음 |
| 에셋 | 임시 아이콘/로고가 정식 에셋으로 교체됨 |
| 상태 | 대기/확정/실패/알 수 없음이 서로 다른 문구·동작을 가짐 |

이 기준은 공식 키움 검수 기준이 아니다. “pixel-perfect 완료”는 공식 폰트·에셋·실기기 캡처 대조와 채널 승인 뒤에만 선언한다. 첨부 미리보기의 완성도와 실서비스의 보안·규제 적합성을 혼동하지 않는다.

## 19. 반드시 금지할 임의 변경

| 하지 말 것 | 이유 / 대신 할 것 |
|---|---|
| 검정/네온/유리효과 Web3 대시보드 | 첨부 간편모드와 다른 제품처럼 보임 |
| 총액 전체를 진한 보라 카드에 넣기 | 원본은 밝은 바탕의 큰 검정 숫자 중심 |
| 모든 필드에 pill 테두리 | 인증 폼의 기본은 밑줄 |
| 모든 카드에 그림자·장식 아이콘 | 원본의 평면 구조/정보 밀도를 훼손 |
| 큰 카드 padding을 12로 줄이기 | 외부 12와 내부 20을 구분해야 함 |
| 모든 텍스트를 12–14로 축소 | 기존 큰 한글 계층이 사라짐 |
| 하단 루트 메뉴 + 지갑 자체 메뉴 중복 | 호스트 내비게이션을 그대로 사용 |
| stock buy/sell 색을 송금/입금 상태에 재사용 | 다른 금융 의미를 혼동 |
| QR처럼 보이는 임의 패턴 | 오송금 위험. 실주소 QR 생성 필요 |
| “보내기” 클릭 즉시 완료 표시 | 네트워크 상태와 고객 승인 절차 누락 |
| 앱 로그인 = 거래 최종 승인 처리 | 호스트 인증/코어 서명 경계 유지 |
| 주민번호·전화·PIN을 데모 하드코딩 | 원본 개인정보를 재사용하지 않음 |
| 촬영 키패드를 직접 재현해 보안 키패드라 부르기 | 기존 보안 SDK 연계 |
| 지갑 UI에 seed/private key/복구 비밀 로깅 | 비밀은 보안 경로와 코어 영역에 한정 |
| 레퍼런스에 없는 기능을 기본 제공으로 확정 | capability/상품 정책을 확인 |
