# 개발 에이전트 실행 지시문

## 목표

제공된 키움 간편모드 스크린샷의 외형을 유지하는 **키움 앱 내 임베디드 지갑**을 구현한다. 새 지갑 브랜드 앱을 디자인하지 않는다. 지갑 기능은 신규 적용안이며 원본 앱에 이미 존재한다고 가정하지 않는다.

## 입력 파일 우선순위

1. `UI_DESIGN_GUIDE.md`의 관찰/추정/확장 구분과 금지 사항.
2. `assets/references/R01-*`–`R18-*`의 실제 외형. `R19-*` 촬영 이미지는 정밀 측정에서 제외.
3. `design/tokens.json`, `design/measurements.json`, `src/kiwoom-wallet.css`.
4. `src/wallet-ui-contract.ts`, `wallet-preview.html`의 화면/상태 예시.

수치와 그림이 다르면 어떤 값이 추정인지 먼저 확인한다. 폰트 미확인 상태에서 크기를 과도하게 줄이거나 이미지 전체를 확대/축소해 맞추지 않는다. 변경할 때 근거·토큰·영향 화면을 기록한다.

## 절대 고정할 외형

- 루트: `#F5F5F5` 바탕, 흰 카드, 카드 외부 가로 12 / 내부 가로 20, 상단 내부 24–28, radius 24, shadow 없음.
- 상세/절차: 흰 바탕, 기본 좌우 20, 밑줄 필드, 상단 48 헤더, 하단 52 CTA.
- Primary: `#7D3BDD`, radius 18. 일반 CTA 글자 14/20, 거래 전용 CTA 16/24. 토큰 및 실제 호스트 폰트 비교 후 보정.
- 계층: 대표 금액 28, 루트 헤더 22, 섹션/절차 제목 20, 본문 16, 일반 보조 14, 입력 라벨/오류 12를 시작값으로 사용.
- 시트: 50% 딤, 상단 radius 16, 손잡이 추가하지 않음, 선택행 높이 52 / radius 16 / gap 10.
- 키움 루트 메뉴 5개 유지. 자산 탭 안에 진입. 새로운 6번째 지갑 탭·took 로고·지갑 자체 전역 메뉴를 만들지 않음.
- 매도 보라/매수 코랄은 매매 전용. 일반 송금은 Primary 보라, 받기는 중립 Secondary.

## 진행 순서

| 단계 | 산출물 | 완료 기준 |
|---|---|---|
| 1. 호스트 확인 | font / viewport / inset / root-header / tabs / navigation 계약표 | 호스트가 그리는 것을 지갑에서 중복하지 않음 |
| 2. 기본 컴포넌트 | 셸, 카드, 버튼, 필드, 선택시트, 탭, 자산행 | R10/R15/R16 비교 캡처를 제출 |
| 3. 지갑 화면 | W00–W09. 신규 화면 범위는 capability로 조절 | 큰 숫자·원화 입력·체인·주소·수수료가 읽힘 |
| 4. 상태 | 로딩/빈 상태/검증/제한/견적만료/승인/확정대기/완료/실패/unknown | 미리보기 성공 플래그를 실거래에 사용하지 않음 |
| 5. 실연계 | 실제 quote·승인·서명·상태·복구 bridge | UI가 키·비밀·보안 인증을 직접 구현하지 않음 |
| 6. 검수 | 320/360/390/430, 큰 글자, 키보드, sheet focus, 원본 비교 | `qa/ACCEPTANCE_CHECKLIST.md`에 근거 기록 |

## 시각 검수에서 먼저 맞출 것

648px 원본을 360 logical px로 정규화한 **비교 가정**을 사용한다. 실제 단말의 dp/DPR이라고 단정하지 않는다. 가로 경계 → 세로 위치 → 실제 폰트/weight → 글자폭/행간 → 아이콘 광학 크기 → 평면색 순으로 조정한다. 일반 CTA, 시트 선택행, 입력 라벨은 서로 다른 글자 크기다.

폰트·아이콘은 원본 리소스를 요청하고 교체 가능한 slot으로 둔다. 제공 SVG와 로고 크롭은 검수용이다. 정식 에셋을 확보하기 전에 “완전 동일” 또는 “pixel-perfect 승인 완료”라고 보고하지 않는다.

## 기능/보안 경계

기존 로그인·보안 키패드·생체/PIN·카메라 권한을 호스트로 연결한다. 주민번호/휴대폰 인증을 지갑에서 새로 수집하지 않는다. 실제 지갑 코어가 반환하는 자산/체인/수수료/정책/거래상태/복구 프로파일을 사용한다. MPC 또는 SAR를 UI에 고정하지 않는다. 고객의 최종 거래 승인은 로그인 상태와 별개로 처리한다.

수신처·자산·네트워크·금액·수수료·견적이 바뀌면 기존 승인 상태를 폐기한다. 견적이 만료되면 재확인한다. `broadcasted`는 `confirmed`가 아니다. 결과가 unknown이면 먼저 조회·대사하고 동일 거래를 다시 보내지 않는다. 주소·수량은 잘라 저장하지 않는다. 금액 계산은 정밀값을 유지한다.

QR을 임의 도형으로 생성하지 않는다. 실제 수신 주소로 검증된 QR을 만들어야 한다. 데모 주소·고객명·잔액·수수료·개인정보를 실서비스 코드/로그에 남기지 않는다. 제공 `src/preview.js`는 화면 탐색용이며 인증/송금/정밀계산 엔진으로 사용하지 않는다.

## 보고 방식

구현 화면, 사용 토큰, 원본 대비 캡처, 남아 있는 대체 에셋, 연결되지 않은 bridge, 실패/미검증 항목을 구분해 보고한다. 원본과 다른 기능·화면은 “지갑 확장”으로 표시한다. 확인되지 않은 규제 판단·지원망·수수료 무료·자산 안전 보장을 UI 문구로 만들어 넣지 않는다.
